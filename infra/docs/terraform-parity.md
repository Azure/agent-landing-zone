## Interpretation

- Each capability is assessed independently for `standalone-standard` and `standalone-network-isolated`.
- Bicep standard means `deploymentMode=standalone` and `networkIsolation=false`: public access without mandatory VNet, private endpoints, firewall, Bastion, NAT, or private DNS.
- Bicep network-isolated means `deploymentMode=standalone` and `networkIsolation=true`: VNet, private endpoints, firewall, Bastion, NAT, and private DNS.
- Terraform `flag_platform_landing_zone=false` approximates only network-isolated standalone. Its required VNet/subnets/private endpoints and disabled-public-access defaults cannot represent standalone-standard.

## Status and evidence

- **full**: static source inspection found the capability; **partial**: only part is present; **absent**: no equivalent was found; **blocked**: target topology or provider structure prevents the scenario.
- **static**, **proposal**, **merged**, **deployed**, and **reviewed** describe evidence maturity, not support.
- `parityDeclared` stays false until the same scenario and target commit have both a successful deployment and an approved reviewed comparison. Plans and static checks never prove parity.
- Input defaults use JSON-native values when `representation=literal`. `representation=expression` stores the exact compiled ARM expression, including its outer brackets; `representation=none` identifies a required input with no default.

## Baseline advancement

Under [proposed ADR-0006](adr/0006-release-metadata-and-comparison-baselines.md), release metadata is independent of this historical comparison. Advancing `parity/config.json` and `parity/inventory.json` requires a separate reviewed change, complete surface coverage, regeneration of this document, and explicit treatment of historical record references. A manifest version bump neither advances these pins nor rewrites records, approvals, handoffs or digests; never follow a moving branch or tag silently.
