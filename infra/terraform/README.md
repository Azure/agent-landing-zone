# Integrated Terraform root

This root is part of the Agent Landing Zone foundation (ADR-0028). Its domain
files compose a single dependency graph, not separate apply stages. It does
not build application images or publish hosted-agent versions.

Operator guidance belongs in the
[central Agent Landing Zone documentation](https://azure.github.io/AI-Landing-Zones/agent-landing-zone/).
Integration and deployed scenario qualification are still required; formatting,
declaration coverage and mocked plans are not Azure parity evidence.

## Input boundary

`variables.tf` declares all 213 Bicep options with camelCase names and typed
collections, plus nine Terraform-only deployment-context and ownership inputs
(222 inputs total). Effective product
defaults include `agent-lz`, disabled Bing, no zone redundancy, and the product
model/container definitions. Nullable jumpbox/Bastion/NAT flags retain their
precedence over legacy `deployVM`. Name inputs accept null/empty to select a
generated name. `location` may inherit a lookup-owned root group's location;
a newly owned root requires an explicit location.

`main.parameters.json` and the typed shared resolver are the product input
sources. The shared Python adapter materializes `infra/terraform/main.tfvars.json`
locally before the native azd lifecycle. This is **generated, ignored native
JSON**, not a committed placeholder template and not an ARM parameter envelope.
Omitted inputs use the root's declared defaults; booleans, numbers, nulls and
typed collections remain native JSON values. There is no separate set of
per-input azd transport variables to populate or persist.

The adapter serializes dollar characters as `\u0024`. This lets native azd
render the generated JSON without substituting literal `${...}` or `$()`
inside application settings or secrets; JSON decoding restores the original
strings. Do not replace these escapes with live placeholders or commit the
generated input file. The adapter owns operator aliases, topology resolution
and sensitive-input handoff; shared hooks own generation and environment binding.

Generated and rendered tfvars, plans, state and azd environment files may contain secrets:
keep them untracked and access-controlled. Sensitive input markers do not
remove secrets from Terraform state. A shared checkout must not regenerate
another environment's inputs during an active lifecycle operation.
For a managed jumpbox, null/empty `vmAdminPassword` requests a persistent
state-owned random password; a supplied password remains a sensitive override.
The compute domain owns that credential and consumes it directly, never
through an output or a new random value generated by a lifecycle hook.

The Terraform-only `azureCloud` context is a typed object with exactly
`environment` and `storage_dns_suffix` string keys. The adapter resolves the
selected cloud/`ARM_ENVIRONMENT` into this object; provider configuration uses
`azureCloud.environment`, and `deployment_context.storage_suffix` uses
`azureCloud.storage_dns_suffix`. The default is the qualified Public pair:

| Provider environment | Storage DNS suffix |
| --- | --- |
| `public` (default) | `core.windows.net` |
| `usgovernment` | `core.usgovcloudapi.net` |
| `china` | `core.chinacloudapi.cn` |

These pairs match the installed AzureRM provider's environment names and Azure
CLI cloud suffix metadata (`azure/cli/core/cloud.py`). Unknown environments and
mismatched pairs fail input validation. The adapter, provider and backend cloud
handoffs must agree before lifecycle execution. This is native deployment
metadata, not a manually configured runtime key. `acrDnsSuffix` remains an
independent registry DNS override and never selects or validates the storage
cloud. No external data source, CLI call or provisioner resolves cloud context
inside Terraform.

## Resource-group ownership and ordering

Ownership is opt-in and explicit:

| Destination | Name input | Create/own input (default `false`) |
| --- | --- | --- |
| Root/Foundry | `resourceGroupName` | `createResourceGroup` |
| Application | `applicationResourceGroupName` | `createApplicationResourceGroup` |
| Networking | `networkResourceGroupName` | `createNetworkResourceGroup` |

Empty application/network names select the root group. Shared groups are
deduplicated. A distinct group shared by application and networking must have
consistent ownership flags. `false` means a data lookup only: BYO groups must
not be imported implicitly or deleted. `true` means Terraform creates the group
and includes it in its destroy boundary; preProvision must **not** create that
same group imperatively. Do not change these flags on an existing state as an
adoption/import mechanism.

Domain resources should consume `deployment_context.foundry_rg_id`,
`application_rg_id`, or `network_rg_id`, or an equivalent explicit dependency,
so creation waits for a new group. BYO VNet, DNS, registry and private-endpoint
placement retain their separate ownership contracts. The state backend must be
outside every workload-owned group's teardown boundary.

The adapter records the exact backend address in private
`terraform-backend.json` before emitting inputs. Restore that record with the
original resource-group and application bindings on a clean runner. Preparation
and teardown reject retargeted addresses or missing deployment ownership.

## Naming and outputs

Generated names preserve CAF and legacy modes, service prefixes, legal length
limits and explicit override precedence. Terraform's default token is the
first 13 hex characters of SHA-256 over JSON
`[lower(subscriptionId), environmentName, lower(effectiveLocation)]`. This is
stable but intentionally **not** Bicep/ARM `uniqueString` byte compatibility.
Do not switch providers for an existing environment. Explicit overrides are
validated, never silently rewritten.

`outputs.tf` exports exactly the existing 64 uppercase lifecycle names.
Disabled scalar values are concrete empty strings/false. The hosted handoff
remains a JSON-serializable object, including its nullable nested members.
`HOSTED_AGENT_PREPARED` means prerequisites selected, not that a hosted runtime
exists. `PUBLIC_INGRESS_LIVE` is configuration intent, not a health probe.
No password, key or connection-string output is exported. Shared configuration
continues to own platform-outputs-v1 publication and runtime discovery beyond
these 64 outputs; do not treat an output name as proof of resource readiness.

## Local checks and native azd caveats

With the composition assembled and the committed dependency lock present:

```powershell
terraform -chdir=infra/terraform fmt -check
terraform -chdir=infra/terraform init -backend=false -lockfile=readonly
terraform -chdir=infra/terraform validate
terraform -chdir=infra/terraform test -filter=tests/root.tftest.hcl
python -m pytest tests/test_terraform_interface.py -q
```

Root tests use mock providers and plan-only runs. They check product defaults,
optional/hosted contexts, output shapes, naming, invalid combinations and group
ownership. No Azure operations are required for these checks.
On Windows, use `-filter='tests\root.tftest.hcl'`; confirm that the runner
actually discovers the test cases rather than reporting zero executed tests.

The verified azd 1.37.1 contract uses `infra.provider: terraform`,
`infra.path: infra/terraform` and default `infra.module: main` in `azure.yaml`;
provider selection and shared hooks are owned outside this root. azd renders
inputs into `.azure/<env>/infra/terraform/`. Do not commit the generated input file.

azd 1.37.1 initializes with `-upgrade`; enforce the committed provider lock
readonly in the separate validation gate, not by injecting a conflicting
`TF_CLI_ARGS_init=-lockfile=readonly` into live azd. Exact provider constraints
and separately pinned AVM versions belong to the state/dependency workstream.
azd also passes `-lock=false` to plan/apply, disabling the Azure Blob lease
state lock. There is no native override in that version. The operational
model permits local azd for individual environments. Shared and production
states require one authorized executor with queued, non-canceling serialization
for the backend subscription, account, container and state key, plus exclusive
state write permissions. Branch-specific queues do not serialize other writers.
These controls do not restore native locking; their enforcement and recovery
need separate evidence. This root supplies no locking wrapper or environment hack.
